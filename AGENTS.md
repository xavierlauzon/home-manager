# AGENTS.md — Home Manager config (Xavier's `~/src/home-manager`)

Project instructions for agent sessions in this repo. Read this first; it is a
table of contents — depth lives in the modules and `docs/`.

## 1. Scope & repo model

- **flake.nix** — entrypoint. Defines `homeConfigurations` for every
  `<hostname>.<username>` pair. Each config passes `extraSpecialArgs`
  (`org`, `role`, `hostname`, `username`, `displays`, `display_center`,
  `networkInterface`, plus `inherit inputs outputs`). Modules read these via
  `specialArgs`, NOT by guessing.
- **home/** — org-isolated configs. `common/` (shared by all users), `xl/`
  (Xavier Lauzon org), `sd/` (second org). Under each: `hostname/`, `role/`,
  `user/`. `home/default.nix` imports `./common` then `./${org}` if it exists.
- **modules/** — reusable modules: `applications/{cli,gui}`, `desktop/`
  (`displayServer`, `shell`, `utils`, `windowManager`), `feature/`, `service/`.
  `modules/default.nix` imports them all.
- **overlays/** — `additions`, `modifications`, `stable-packages`,
  `unstable-packages`.
- **pkgs/** — package overrides/nix expressions (firecrawl-mcp, komodo-mcp-server…).
- **dotfiles/** — config files NOT yet migrated to nix. Treat as temporary.
- **nixos/** — small NixOS bits (sunshine-prereqs). Home-manager is the main scope.

## 2. Users, hosts, and the two nixpkgs channels

- Users: `xavier` (gn), `xavierlauzon` (gnsn, sd org), `sam`.
- Hosts (org xl): `xavierdesktop`, `blackhawk` (x86_64-linux, workstation);
  `raptor`, `trident`, `falcon`, `spectre` (aarch64-linux, server);
  `paveway`, `hellfire`, `maverick` (xl servers).
- Hosts (org sd): `bohr`, `turing`, `pasteur`, `banting`.
- **Two channels**: `nixpkgs-stable` (release-26.05) and `nixpkgs-unstable`.
  Most configs default to stable; a host is put on unstable via
  `nixpkgs = nixpkgs-unstable;` in its `HomeConfiguration`. The matching
  home-manager (stable/unstable) is chosen automatically. Do not mix
  `nixpkgs` versions inside one config.

## 3. Ground rules

- **Smallest change.** One host/feature per commit; don't refactor unrelated
  code while touching a module.
- **Respect org isolation.** Config in `common/` affects every user — put
  org- or user-specific stuff under `xl/` or `sd/`, never in `common/`.
- **Never commit secrets.** See section 5.
- **Modules read `specialArgs`, not global env.** If you need a new fact,
  thread it through `extraSpecialArgs` and the module's function args.

## 4. Quick start workflow

```sh
# Format (alejandra is the formatter; in PATH)
alejandra .

# Validate a config WITHOUT switching (evaluate + typecheck)
nix flake check .#homeConfigurations.blackhawk.sam.config   # or `nix flake check`

# Build (dry-run) vs switch (apply)
home-manager build --flake .#blackhawk.sam
home-manager switch --flake .#blackhawk.sam

# The current machine's own config
home-manager switch --flake .#blackhawk.sam
```

- Never `home-manager switch` a config you haven't `build`ed/checked first.
- Finding options: `rg "option" modules` and `man home-configuration` /
  `home-manager` search. Do not invent option names — check
  `nix eval` or the home-manager docs before adding an unknown option.

## 5. Secrets & safety (sops-nix)

- Secrets live under `home/*/secrets/**` and are encrypted with **sops + age**.
  `.sops.yaml` maps `path_regex: home/*/secrets/.*` to the age keys.
- **Never read or edit the encrypted files.** `decrypted/` is gitignored — the
  decrypted tree is generated by sops-nix on activation, never committed.
- Adding a secret: `sops --age $(cat key) home/xl/user/sam/secrets/<name>/default.nix`
  (or edit an existing one with `sops`). Then reference it in config via
  `config.sops.secrets.<name>` / `sopsFile`, never inline the plaintext.
- **Deploy-after-eval, not deploy-first.** Build/check locally, confirm the
  diff, then `switch`. A broken eval must never reach a host.

## 6. Change review checklist

Before considering a change done:

- [ ] Scoped to the intended host/feature; no unrelated edits
- [ ] `alejandra .` run (no diff left)
- [ ] `nix flake check` / build passes for the affected config
- [ ] No secrets committed; no `decrypted/` staged
- [ ] `specialArgs` correct for the target host/user
- [ ] Summary of the change given (what changed and why)

## 7. Known gotchas

- `node/npm/bun` are NOT on PATH globally — the user's dev work often needs
  `nix shell nixpkgs#nodejs_22 --command npm ...` (see `modpack-hub` AGENTS.md).
- `opencode` CLI is installed as `opencode2` (v2.1.0) in the user profile;
  opencode config under `~/.config/opencode/` is nix-managed (symlinked).
- `result` is a gitignored symlink to the last generation.
